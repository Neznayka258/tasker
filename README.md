# Tasker

## Назначение и польза
Tasker — настольный планировщик задач на PySide6. Приложение позволяет создавать, редактировать и удалять задачи, отмечать их выполнение, а также отфильтровывать список по статусу, типу и сроку выполнения. Проект можно использовать как учебный пример приложения с локальной SQLite-базой и кастомными темами.

## Подход к развертыванию
- исходный код хранится в рабочем каталоге; публичный интерфейс запуска — `main.py` в корне;
- вся реализация UI находится в `src/`, а база данных по умолчанию создаётся в `data/tasks.db` (каталог создаётся автоматически, не требуется ручная подготовка);
- зависимости фиксируются в `requirements.txt`; рекомендуется виртуальное окружение;
- переменные окружения (например, альтернативные пути к БД) выносятся в `.env`, который не следует добавлять в Git.

## Инструкция по установке и запуску (Windows)
1. **Создайте виртуальное окружение**
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\activate
   ```
2. **Установите зависимости**
   ```powershell
   pip install --upgrade pip
   pip install -r requirements.txt
   ```
3. **(Опционально) настройте `.env`** — см. раздел ниже.
4. **Запустите приложение**
   ```powershell
   python main.py
   ```
   Главное окно откроется с таблицей задач и доступными фильтрами.

## Переменные окружения (.env)
Создайте файл `.env` в корне проекта и храните в нём чувствительные или системные настройки:
```
DB_PATH=C:\path\to\custom\tasks.db
THEME=light
```
В коде можно подключать `python-dotenv` или иной загрузчик переменных. Сам `.env` должен быть добавлен в `.gitignore`.

## Requirements
Все внешние зависимости перечислены в `requirements.txt`. Алгоритм:
1. создать venv;
2. `pip install -r requirements.txt`;
3. фиксировать изменения командой `pip freeze > requirements.txt`, если добавляете новые пакеты.

## Соответствие шаблону
- **README.md** — текущий файл, описывает назначение, развёртывание и запуск.
- **.gitignore** — используйте стандартный шаблон, дополните правилами для `.venv/`, `.env`, `data/` (если не хотите хранить БД в Git), кешей IDE и тестовых данных (`*.png`, `*.docx`, `datasets/` и т.д.).
- **.env** — не хранится в репозитории; в нём можно задавать пути к БД, API-ключи, токены и другие секреты.
- **requirements.txt** — содержит зависимости PySide6 и др. библиотек.
- **test/** — пока отсутствует; тесты можно вынести сюда при расширении проекта.
- **storage/** — не используется; при необходимости можно создать под альтернативные БД или векторные индексы.
- **src/** — содержит логику приложения. Структуру по подпапкам (`api/`, `core/`, `models/`, `services/`, `utils/`) можно ввести по мере роста проекта; сейчас всё относится к GUI-части.
- **preload_data/**, **logs/**, **experiments/**, **config/** (подпромпты) — не требуются для текущей версии, но их можно добавить при появлении соответствующего функционала (предзаполнение БД, логирование, Jupyter-эксперименты, промпты для LLM и т.д.).
- **data/** — содержит SQLite-базу (`tasks.db`). Папка создаётся автоматически кодом `db_manager.py`, поэтому достаточно убедиться, что у процесса есть права на запись.

При добавлении новых компонентов ориентируйтесь на шаблон: выносите общую бизнес-логику в `services/`, конфигурации в `core/`, а API/боты в `api/`. Это упростит сопровождение и масштабирование Tasker.
